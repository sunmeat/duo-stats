# Duolingo Stats

Маленький локальный сайт на React: показывает статистику профиля Duolingo по
никнейму — аватар, имя, страйк, XP и разбивку по курсам, отсортированную от
большего к меньшему. Есть шаринг: короткая ссылка вида `?u=nickname` и
экспорт карточки в PNG.

## Запуск

Нужен установленный Node.js (18+).

```bash
npm install
npm run dev
```

Откроется `http://localhost:5173`. По умолчанию показывается профиль
`taemnus`, можно ввести любой другой никнейм в поле поиска.

## Как это работает

Данные берутся из **неофициального публичного** API Duolingo:

```
https://www.duolingo.com/2017-06-30/users?username=<nick>&fields=...
```

Он отдаёт JSON без авторизации (тем же способом пользуется duome.eu). Но у
браузера напрямую сходить туда не получится — Duolingo не присылает
CORS-заголовки, поэтому `fetch` из браузера будет заблокирован политикой
CORS. Решение — прокси в `vite.config.js`: браузер стучится на
`/duoapi/...` на локальном dev-сервере, а сам vite (уже не браузер, значит
CORS не действует) перенаправляет запрос на `duolingo.com` и отдаёт ответ
обратно. Поэтому сайт работает только через `npm run dev` (или через свой
прод-сервер с таким же проксированием) — открыть `index.html` напрямую
файлом не выйдет.

### Что доступно публично, а что — нет

Через этот эндпоинт **без токена** доступны: никнейм, имя, аватар, страйк
(и лучший страйк), суммарный XP, список курсов (язык, название, XP,
короны), дата регистрации, статус Super.

**Недоступны публично**: текущая лига (leaderboard/league) и количество
алмазов/рубин (gems/lingots). Duolingo отдаёт их только в приватном API,
который требует JWT-токен именно вашего залогиненного аккаунта — по чужому
нику их получить нельзя в принципе, только по своему. В карточке эти поля
показываются как «нет публичных данных».

Если эти два поля вам обязательно нужны — единственный легальный вариант:

1. Залогиниться на duolingo.com и достать `jwt` из cookies (DevTools →
   Application → Cookies).
2. Ходить с этим токеном в приватные эндпоинты (`/2017-06-30/users/<id>`
   с заголовком `Authorization: Bearer <jwt>`, есть в описании неофициальных
   библиотек, например `KartikTalwar/Duolingo` на GitHub).
3. Это будет работать **только для вашего собственного аккаунта**, не для
   произвольных ников — Duolingo не отдаёт лигу/алмазы чужих пользователей
   никому, включая duome.eu.

Если найдёте официальный API-ключ с доступом к этим полям — просто
замените реализацию `fetchDuolingoUser` в `src/api/duolingo.js`, вся
остальная вёрстка (`user.league`, `user.gems.diamonds`,
`user.gems.rubies`) уже готова их принять.

## Структура проекта

```
duo-stats/
├── index.html
├── vite.config.js        # прокси для обхода CORS
├── package.json
└── src/
    ├── main.jsx
    ├── App.jsx            # состояние, загрузка, URL-шаринг
    ├── styles.css
    ├── api/
    │   └── duolingo.js    # запрос + нормализация ответа Duolingo
    └── components/
        ├── SearchBar.jsx
        ├── ProfileCard.jsx
        ├── CourseList.jsx
        └── ShareBar.jsx   # копирование ссылки + экспорт PNG
```

## Продакшен-сборка

```bash
npm run build
```

Важно: `npm run build` (`vite build`) даёт статику, но прокси из
`vite.config.js` работает только в dev-режиме (`vite dev`). Если захотите
задеплоить собранный сайт на реальный хостинг — понадобится свой бэкенд
(например, маленький Express/Cloudflare Worker), который так же
проксирует запросы к `duolingo.com`, иначе браузер снова упрётся в CORS.
